# mp_Tools UI 設計規格

> 這份文件是 `prototype/index.html` 的文字版。原型是視覺基準，本文件說明「為什麼長這樣」與「React 版要怎麼實作」。
> 所有 token 名稱與原型、與 `apps/web/src/styles/tokens.css` 三邊一致，可直接對照。

---

## 1. 設計立場

**一句話：** 這是一個「工作臺」，不是一個「網站」。

參考的三個專案都是**單頁、單一任務**的工具（裝固件、開 REPL）。mp_Tools 要做的是把它們合起來，所以介面最大的敵人不是醜，而是**失焦** —— 使用者開起來會不知道現在該按哪裡。

三個決定：

### 1.1 裝置永遠在畫面上（Board Strip）

頂部 56px 的橫條是「裝置台」。它顯示每一個已連線的裝置，用一個小圓形 LED 表示狀態：`暗` 未連線 / `脈動綠` 連線中 / `恆亮綠` 閒置 / `琥珀` 忙碌 / `紅` 錯誤。點它切換作用中的裝置。

**理由：** 序列埠工具最常見的災難是「我以為我在對 A 板燒錄，其實是 B 板」。把「目前作用中的裝置」變成一個永遠可見、可點選的實體，比在選單裡選 COM port 誠實得多。

### 1.2 一個 canvas，五個模式，不是五個分頁

左側 rail 切換 `編輯` / `燒錄` / `監控` / `套件` / `裝置`。**切換時 bottom panel（REPL）不會消失** —— 因為「燒錄完馬上打指令」是最常見的連續動作，不該強迫使用者切回來。

**理由：** 分頁會讓狀態分裂（編輯器 dirty、REPL 歷史、燒錄進度）。用一個固定的 canvas + 一個固定的 bottom panel，狀態永遠只有一組。

### 1.3 危險動作用「琥珀」，不用「紅色」

紅色只給「已經發生的錯誤」。`Erase flash`、`覆蓋裝置上的 main.py` 這類**尚未發生但可能後悔**的動作，用琥珀 + 明確的後果句子（「這會刪除裝置上全部 12 個檔案」），不用紅色。

**理由：** 紅色按鈕會被使用者當成「裝飾」而習慣性忽略。留在錯誤訊息上用，才有訊號價值。

## 2. 視覺語言

### 2.1 色票

方向：**暗色、暖中性、低飽和。** 不要藍紫漸層（那是 AI 生成的預設值），不要純黑 `#000`（在 OLED 以外的螢幕上死板）。

```css
/* 基底：暖中性灰，往藍偏一點點避免發黃 */
--bench-950: #0b0c0e;   /* 應用最底層背景 */
--bench-900: #101216;   /* rail / 側欄 */
--bench-850: #15181d;   /* panel 背景 */
--bench-800: #1b1f26;   /* 卡片 / 輸入框 */
--bench-700: #262b34;   /* 邊框（預設） */
--bench-600: #39404d;   /* 邊框（hover / 強調） */
--bench-400: #6b7486;   /* 次要文字、停用 */
--bench-200: #aeb6c4;   /* 一般文字 */
--bench-100: #e4e8ef;   /* 標題文字 */

/* 語意色：只有四個，不准再加 */
--led:        #2fe0a8;  /* 通電 / 連線 / 成功 */
--led-dim:    #14654c;  /* LED 的暗態、進度條底 */
--amber:      #f0a53c;  /* 忙碌 / 警告 / 需確認的破壞性操作 */
--danger:     #ff5a5f;  /* 已經發生的錯誤 */
--solder:     #58c4dc;  /* 連結 / 資訊 / 選取焦點 */
```

**用色紀律：** 畫面上 90% 的面積是 `bench-950/900/850`。`led` 與 `amber` 只出現在**小而關鍵的地方**（LED 點、進度填充、作用中的 rail 圖示）。`solder` 只用於文字連結與 `:focus-visible` 外框。**如果一個畫面同時出現三種彩色，就是設計錯了。**

### 2.2 字體

字體必須在 11px 還讀得清楚 —— 這是資料密集型工具，不是行銷頁。所以 display 字體選窄幅無襯線（可壓縮），不用襯線（小字會爛掉）。

```css
--font-display: "Archivo", system-ui, sans-serif;       /* 標題 / 板名 / 區段標籤 */
--font-ui:      "IBM Plex Sans", system-ui, sans-serif;  /* 一般介面文字 */
--font-mono:    "IBM Plex Mono", ui-monospace, monospace;/* 程式碼 / 位址 / 讀數 / 日誌 */
```

**規則：**
- **所有數字讀數都用 `--font-mono`** —— 十六進位位址、位元組數、記憶體、速率。等寬字讓數字不會跳動。
- 區段標籤用 `--font-display`，`11px`、`letter-spacing: 0.08em`、`text-transform: uppercase`。這是整個介面的「節拍器」，讓密集的畫面有結構。
- 程式碼一律 `13px / line-height 1.6`。不要在編輯器裡用 12px 以下。
- 字型用 `@fontsource/*` 自我託管（npm 套件），**不要**連 Google Fonts CDN —— 這個工具要能離線用。

### 2.3 間距與尺寸

4px 基準。`4 / 8 / 12 / 16 / 24 / 32`，不要出現 5、7、10 這種數字。

| 元素 | 尺寸 |
|---|---|
| Activity rail 寬 | 64px |
| Board strip 高 | 56px |
| 側欄寬 | 288px（可拖曳 200–480） |
| Bottom panel 高 | 預設 240px（可拖曳 120–70vh） |
| Status bar 高 | 28px |
| 圓角 | `4px`（控制項）/ `8px`（面板）/ `full`（LED、pill） |
| 邊框 | 一律 `1px solid var(--bench-700)` |

**不要用陰影做層次。** 用邊框 + 背景明度差。陰影在暗色介面上看起來像污漬，而且會讓密集的畫面變髒。唯一的例外是浮動選單與對話框：`0 16px 48px -12px rgb(0 0 0 / 0.6)`。

### 2.4 質感（克制地用）

- **電路板點陣**：主 canvas 背景是 16px 間距的 `radial-gradient` 點陣，`--bench-700` 的 12% 透明度。在空白區域提供「這是一塊板子」的暗示，有內容時被蓋住。
- **區段標題的掃描線**：panel header 底部一條 1px 的漸層（透明 → `bench-700` → 透明），像示波器的刻度線。**只在 header 用，不要濫用。**
- **LED 的脈動**：連線中 `animation: pulse 1.4s ease-in-out infinite`，只改 `opacity` 與 `box-shadow` 的半徑。**尊重 `prefers-reduced-motion`。**

### 2.5 動效

只有三種，都很短：

| 動作 | 時長 | 曲線 |
|---|---|---|
| hover / focus | 120ms | `ease-out` |
| panel 展開、rail 切換 | 180ms | `cubic-bezier(0.2, 0.8, 0.2, 1)` |
| flash map 區塊填充 | 跟隨實際寫入進度 | 無（線性） |

**不准做的：** 進場動畫、整頁淡入、元件逐一浮現。這是一個每天開二十次的工具，第二次之後所有動畫都只是延遲。

## 4. 設計簽名：Flash Map

這是整個介面唯一「會被記住」的元素，也是它與 Adafruit flasher 的差別。

傳統進度條只說「寫了 62%」。但 flash 不是一條線，是**一段有位址的空間**。所以燒錄進度用一張記憶體地圖表示：

```
   0x0 · bootloader  0x8000 · partitions  0x10000 · firmware          0x1D0000
   ┌────────────────┬──────────────────┬──────────────────────────┬──────────────┐
   │ ✓ bootloader   │ ✓ partitions     │ firmware                 │ 未使用        │
   │ 24 KB          │ 3 KB             │ 1.42 MB                  │ 2.19 MB      │
   │                │                  │▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░│░░░░░░░░░░░░░░│
   └────────────────┴──────────────────┴──────────────────────────┴──────────────┘
   前兩段（bootloader + partition table，共 27 KB）只佔 4 MB flash 的 0.66%，
   圖上以最小寬度繪製並以虛線標示，只有 firmware 之後按真實比例。
   ┌──────────────────────────────────────────────────────────────────────────────┐
   │ [寫入中 62%]   ESP32-S3 · 4 MB · dio                    2.1 MB/s · 剩 ~3s    │
   └──────────────────────────────────────────────────────────────────────────────┘
```

**為什麼不純按比例畫（這是實作時一定會踩到的坑）：**
真實的 ESP32 layout 是 `bootloader @0x0`(24 KB)、`partition table @0x8000`(3 KB)、`app @0x10000`(1.42 MB)。
前兩段總共只佔 4 MB 的 **0.66%**。若老實按位元組數分配寬度，這兩段的標籤會疊成一團、完全讀不到
（原型實測：兩段的可用寬度各只有 18px）。

所以採用業界畫 memory map 的慣例 —— **低址區給固定最小寬度，並誠實標示哪裡不按比例**：

- 每段寬度 = `max(minWidth, round(bytes / totalBytes * 1000))`，`minWidth` 由標籤長度決定（`bootloader` 需 94px、`partitions` 需 96px）。
- 軸上的刻度用**虛線**標出「不按比例」的區間；`0x0 / 0x8000 / 0x10000` 三個位址都必須出現在軸上。
- 地圖下方固定一行說明，寫出被壓縮的區段與其實際佔比。**不要因為難看就省略這行** —— 沒有它，這張圖就是錯的。
- 每一段的實際位址與大小同時放在 `title` 屬性（hover 可看完整檔名），因為小區段的文字一定會被截斷。

**其餘實作要點：**
- `未使用` 區域用斜線紋理（`repeating-linear-gradient`）表示，不用顏色；它也**永遠不會**進入 `done` 狀態（它沒有東西被寫入）。
- 每段左上角標名、下方標大小。已完成的段落標 `✓` 並把填滿色換成 `--led`。
- 三段是**依序**燒的（esptool 一次燒一個檔案），所以狀態機的門檻是 `bootloader` 8% → `partitions` 24% → `app` 100%，不是三段同時跑。
- 寫入中那一段用 `--amber` 填充；錯誤時整段變 `--danger` 並在下方直接顯示原始錯誤訊息（不要只給「燒錄失敗」四個字）。
- 這個元件的資料來源就是 `esptool-js` 的 `fileArray`（每項有 `address` 與 `data.length`），加上當下的 chip 總 flash 大小。**不需要額外協議支持。**

## 5. 元件清單

每個元件列出**必要狀態**。少一個狀態就是沒做完。

### 5.1 `BoardStrip` / `BoardTicket`
頂部裝置台。
- 狀態：`empty`（無裝置 → 顯示虛線框「+ 連線裝置」）· `connecting` · `idle` · `busy` · `error` · `multiple`（多裝置時可橫向捲動，作用中的有 `--bench-600` 邊框與左側 2px `--led` 指示條）
- 互動：點擊切換作用中 · 雙擊開啟裝置面板 · 右鍵選單（重新連線 / 中斷 / 複製裝置資訊 / 忘記這個埠）

### 5.2 `ActivityRail`
64px 圖示列。五個項目：`編輯` `燒錄` `監控` `套件` `裝置`。
- 狀態：`default` · `hover` · `active`（左側 2px `--led` 條 + 圖示變 `--bench-100`）· `disabled`（無裝置時 `燒錄`/`監控` 灰掉，hover 顯示提示「需要先連線裝置」）· `badge`（燒錄中有小圓點）
- 底部固定兩個：`設定`、`說明`

### 5.3 `DevicePanel`（側欄 · 裝置）
晶片的身份證。用 **definition list**，不要用卡片。
```
CHIP          ESP32-S3 (QFN56) rev v0.2
MAC           7c:df:a1:xx:xx:xx
FLASH         4 MB · dio · 80 MHz
FIRMWARE      MicroPython v1.24.1 on 2024-11-29
FILESYSTEM    2.0 MB 總計 · 1.34 MB 可用   [▓▓▓▓▓▓░░░░]
FREE HEAP     184 KB / 320 KB               [▓▓▓▓▓▓▓░]
UPTIME        00:14:22
```
- 讀數每 2 秒更新，但**只有在裝置閒置時才輪詢**（忙碌時暫停，避免打斷燒錄或執行）。
- 底部三個動作：`軟重置` · `進 bootloader` · `抹除檔案系統`（琥珀）

### 5.4 `DeviceTree` / `LocalTree`（側欄 · 檔案）
- 節點：資料夾（可折疊三角）· `.py` 檔 · `.mpy` 檔（灰色，不可編輯）· 其他
- 狀態：`idle` · `hover` · `selected` · `uploading`（該節點下方一條 2px 琥珀進度線）· `error`（紅色 `!` 圖示 + tooltip 顯示裝置原始錯誤）
- 檔案大小用 `--font-mono` 右對齊。
- 拖曳本機檔案進來 → 該資料夾高亮 `--solder` 邊框 → 放開 = 上傳。
- 頂部工具列：`⟳ 重新整理` · `⬆ 上傳` · `⬇ 全部下載` · `＋ 新檔案`

### 5.5 `Editor`
- 分頁列：dirty 標記（`●` 而非 `*`）· 中鍵關閉 · 右鍵「關閉其他 / 關閉全部」
- 狀態：`clean` · `dirty` · `saving` · `readonly`（`.mpy` 或裝置 busy）
- 快捷鍵：`Ctrl-S` 存到裝置 · `Ctrl-Enter` 執行選取（走 paste mode）· `Ctrl-Shift-Enter` 軟重置並執行 `main.py`
- 錯誤標記：執行後若 `parseTraceback()` 有結果，在對應行加 `--danger` 波浪底線，並在該行右側顯示錯誤型別。
- 字型 `--font-mono` 13px；行號欄背景 `--bench-900`；目前行背景 `--bench-800`。

### 5.6 `ReplTerminal`（bottom panel）
- xterm.js，`fontFamily: var(--font-mono)`，`fontSize: 13`，`cursorBlink: true`，`scrollback: 5000`。
- 主題色直接餵上面的 CSS 變數（用 `getComputedStyle` 讀，讓深淺色主題切換時自動跟著換）。
- 標題列右側：`中斷 (Ctrl-C)` · `軟重置` · `清除` · `記錄到檔案`
- 狀態：`no-device`（顯示「連線裝置後這裡會出現 REPL」）· `ready` · `running`（標題列出現琥珀 `執行中` pill 與 `中斷` 按鈕）· `busy`（被燒錄佔用 → 顯示「裝置忙碌中：燒錄」）

### 5.7 `FlashWizard`
四個步驟，左側有步驟指示（`1 選裝置 → 2 選固件 → 3 選項 → 4 燒錄`）。
- Step 1 `BoardStep`：板子卡片清單（可搜尋），或「自動偵測」（已連線時預選）。選完顯示晶片與 flash 大小。
- Step 2 `SourceStep`：三個來源並排 —— `官方最新` / `指定版本` / `本機檔案`。每個固件顯示版本、檔名、大小、SHA256（前 8 碼）。
- Step 3 `OptionsStep`：`抹除整個 flash`（琥珀，勾選後出現二次確認文字）· `寫入後重置`（預設開）· `進階：baud rate / flash mode / flash size`（預設收合，且 flash size 預設 `keep`）
- Step 4 `ProgressStep`：`FlashMap` + 即時日誌（可展開）+ `取消` 按鈕（真的會 abort，不是只改畫面）
- **任何步驟都能看到上方的 Board Strip。** 燒錄中 BoardStrip 的 LED 是琥珀脈動，且「中斷」按鈕變成 disabled 並顯示 tooltip「燒錄中請勿中斷」。

### 5.8 `StatusBar`
`● 狀態 | 晶片 · 固件版本 | 速率 | 檔案系統同步狀態 | 快捷鍵提示`
- 最右側永遠顯示一個提示：閒置時 `Ctrl-K 開啟命令面板`，忙碌時顯示目前的操作與取消鍵。

### 5.9 全域元件
- `Toast`：右上角，最多同時 3 個，`成功` 3 秒自動消失，`錯誤` 要手動關（因為錯誤訊息常需要複製）。
- `CommandPalette`（`Ctrl-K`）：所有動作的統一入口。**這是「綜合工具」的關鍵** —— 當功能多到側欄放不下時，命令面板是唯一能維持可發現性的方法。
- `EmptyState`：每個空白畫面都要有「下一步該做什麼」的按鈕，不要只寫「尚無資料」。

## 6. 關鍵流程

### 6.1 第一次使用（尚未連線）
1. Canvas 顯示：中央一塊板子的線稿輪廓（用 SVG 畫，`--bench-700`），下方一行字「把開發板用 USB 接上，然後」。
2. 一顆大按鈕：`選擇序列埠`。旁邊小字：「需要 Chrome / Edge 89+ · 或下載桌面版」。
3. 若偵測到不支援 Web Serial → 這一步直接換成引導畫面（**不要讓使用者按了才發現不能用**）。

### 6.2 連線後（自動判斷，不問使用者）
連線成功 → 背景依序做三件事，UI 上以 BoardStrip 下方一條細進度線表示：
1. 試 `esploader.main()` 判斷是否為 ESP 晶片（500ms 逾時）
2. 試 raw REPL `Ctrl-C Ctrl-A` 判斷是否為 MicroPython/CircuitPython
3. 抓裝置資訊（版本、記憶體、檔案系統）

判斷完 → 側欄自動切到 `裝置`，canvas 自動切到 `編輯`，bottom panel 自動開 `REPL` 並顯示 banner。
**使用者不需要知道上面三步。** 但若兩個偵測都失敗，要給明確的三選一引導（裝驅動 / 進 bootloader / 換埠）。

### 6.3 燒錄完
燒錄成功 → 自動 `hard_reset` → 自動重新進入 raw REPL → BoardStrip LED 回到綠色 → Toast「燒錄完成，已重新連線」。**不要讓使用者自己按「重新連線」。**

## 7. 無障礙

- 所有互動元素 `:focus-visible` 用 `--solder` 的 2px 外框 + 2px offset。**不要用 `outline: none`。**
- 對比：`--bench-200` 在 `--bench-900` 上 ≈ 9.4:1；`--bench-400` 只用在**非必要**的次要文字，且不低於 4.5:1 的地方要用 `--bench-200`。
- LED 狀態**不能只靠顏色**：`連線中` 同時有脈動動畫、`錯誤` 同時有 `!` 圖示。色盲使用者要能分辨。
- `prefers-reduced-motion`：關掉所有脈動與過場，保留 120ms 的 hover。
- 編輯器與終端機都要能純鍵盤操作（`Ctrl-1..5` 切換 rail、`Ctrl-\`` 切換 bottom panel、`Ctrl-K` 命令面板）。
- 燒錄這種長時操作要能用 `aria-live="polite"` 播報里程碑（「開始寫入」「寫入完成」「重置中」），不要每一 % 都播報。

## 9. 原型實測修掉的問題（別再犯）

這些是在瀏覽器裡實際跑過、量過才發現的。React 版若照著「看起來合理」的寫法重寫，會全部再犯一次。

| 症狀 | 根因 | 修法 |
|---|---|---|
| 編輯器行號與程式碼逐行錯開，到第 19 行差 10px | 行號欄的 `div` 沒有固定高度，用 `line-height` 撐；程式碼欄有固定高度。空行用 `&nbsp;` 又比真空行高 | 兩欄共用同一個 `--lh` 變數設定 `height`；空白行一律用 `&nbsp;` |
| Flash Map 的位址標籤疊成一團 | 低址區只佔 0.66%，絕對定位的標籤全部擠在 5px 內 | 見第 4 節：最小寬度 + 虛線標示 + 說明行 |
| Flash Map 完成時，「未使用」也被標成 `✓` | 狀態機只判斷「進度是否超過門檻」，沒有排除本來就不會被寫入的區段 | 未使用區永遠是 `free` |
| Flash Map 三段同時在跳 | esptool 是**依序**燒檔案，不是平行 | 門檻改成 8% / 24% / 100% |
| 燒錄頁底部的按鈕被下方面板蓋住 | 用固定 `height` 寫死 log 高度，`100vh` 一變就爆 | `height: calc(100vh - <固定偏移>)` 搭配 `min/max-height` |
| 套件列表的「已安裝」徽章被壓成兩行 | flex 子項沒有 `flex: 0 0 auto`，被相鄰的長文字擠壓 | 徽章與按鈕一律 `flex: 0 0 auto; white-space: nowrap` |
| 側欄 `CHIP` 欄位折成兩行 | `dt` 的 `78px` 放不下 `ESP32-S3 (QFN56) rev v0.2` 這種值 | `dt` 縮到 66px、值改用等寬字並允許換行 |
| 徽章被壓成 14px 寬、文字溢出 | `.chip` 是 flex 子項時 `display: inline-flex` 會被 blockify 成 `flex`，Chromium 在此組合下把它的 max-content 寬度算成 0（`flex: 0 0 auto` 也救不了） | `.chip` 明寫 `width: max-content`。**這行不能拿掉。** React 版會遇到一模一樣的問題 |
| 琥珀色的儀表看起來像綠色的 | 儀表只換了填滿色，軌道色（`--led-dim`）沒換，整體讀起來仍是「正常」 | 每個色調都要連軌道色一起換 |
| `file://` 開舊版原型看到的是舊畫面 | 瀏覽器對 `file://` 快取很黏 | 改版後加 `?v=N` 再開（這是原型開發專用的坑，Vite 開發時不會遇到） |
